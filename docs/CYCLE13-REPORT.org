#+TITLE: Obsidian / Monad — Cycle 13: Bounded Live Publication Scheduling
#+DATE: 2026-10-11
#+STARTUP: overview

* Scope

Incremental implementation over Cycle 12. This cycle improves real engine
checkpoint behavior and publication request admission, NOT independent QTT
candidate compilation, which the reviewed MonadC SDK does not yet provide.

* Source changes

- New =src/monad/publication_queue.[ch]=: two owner-thread request lanes with
  deterministic fair dispatch, last-writer-wins BOOT coalescing, idempotent REPL
  submissions, token-checked completion, and cancellation-before-start.
- =runtime.c= routes watched/F5 reloads and REPL submissions through one
  checkpoint; active Monad leases defer both without dropping submitted work.
  Only one potential source compilation is admitted per frame checkpoint.
- Runtime reset/close also reset the queue, so reopening the engine does not
  retain old request tickets or telemetry.
- The GPU REPL exposes =:queue= and =:cancel-boot=. Monad gains
  =publish-queued=, =publish-completed=, =publish-coalesced=,
  =publish-failed=, and =publish-cancelled= foreign calls; native helper
  =(publication-queue)= in =modules/obsidian/live-reload.mon=.
- Startup's explicit =obs_monad_engine_boot_from_environment= remains a
  separate initialization path; scheduling governs runtime requests only.

* Architectural limits

This is not a nonblocking compiler. Each accepted request still invokes the
existing synchronous compiler path on the engine thread. The scheduler
reduces redundant work and defines fair admission, but cannot guarantee
smooth frame timing without detached MonadC candidate images. The engine
cannot independently prove that arbitrary host side effects or persistent
runtime state survive a failed script. QTT quantity evidence and code
publication remain compiler-owned.
