#+TITLE: Obsidian Cycle 21 — Opt-in native/foreign dispatch CPU profiling
#+DATE: 2026-10-11
#+STARTUP: overview

* Purpose

Make performance work evidence-driven by observing the real *host hot paths*
that invoke embedded Monad every frame. This cycle changes neither the MonadC
ABI nor the QTT proof system and does not invent independently compiled native
candidates. Native-image pinning and callback ownership remain unchanged.

* DONE Implementation

- =src/monad/dispatch_metrics.[ch]=: allocation-free, owner-thread-only,
  fixed log2 nanosecond histogram for frame callbacks and pinned camera-native
  policies, separated into setup, execution and total CPU cost. O(1) sample
  insertion, fixed memory, no locks, no per-record sorting or allocation.
- Opt-in =OBSIDIAN_MONAD_PROFILE_FFI=1=; disabled path has only a Boolean check
  and does not call =clock_gettime= or update counters.
- =src/monad/frame_api.c=: scopes timings across foreign frame borrow,
  lease acquisition, Monad procedure invocation, and cleanup. Failing borrows,
  denied leases and failing callbacks increment diagnostic failures. A callback
  is compared with its live slot *before* the retained pointer is released.
- =src/monad/runtime.c=: scopes coherent native-generation pin, function
  lookup, guest native invocation, C camera application and release.
- =src/monad/hotreload_api.c=: nine concise =dispatch-*= read-only procedures;
  =modules/obsidian/live-reload.mon=: pure host-facing helpers.
- =src/monad/repl_service.c=: =:dispatch= reports attempts, failures, upper-
  bound CPU p95 and maximum by lane; no work runs on the GPU callback thread.
- =Makefile=: new headless tests and opt-in benchmark; stricter SDK syntax gate
  for the modified frame and hotreload API through a labelled header fixture.

* Performance evidence

Local Linux/container CPU microbenchmark, GNU C23 =-O3 -DNDEBUG=, two independent
runs of 2,000,000 deterministic alternating frame/camera metric recordings:

| Run | Recorder disabled | Recorder enabled |
|-----+-------------------+------------------|
| 1   | 1.882 ns/record   | 8.967 ns/record  |
| 2   | 1.545 ns/record   | 5.285 ns/record  |

These observations measure *only histogram recorder overhead*, not the
clock calls and not Monad callback performance, native compiler/JIT latency,
or Vulkan GPU/CPU frame times. Frequencies, CPU scheduling and cache state
were not controlled; no speedup claim is drawn from these figures.

The implementation uses log2 buckets; =p95= is the inclusive bucket upper
bound, not a sampled order statistic. No raw frame timestamps or user content
are stored. Recordings reset when the Monad host opens.
