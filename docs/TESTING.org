=./make= is a frontend over the original Makefile, not a replacement for it.
It maps named commands to existing GNU Make targets; all original Makefile
targets, recipes, and direct invocation forms remain available. =./make test=
and =make test= run the same default suite. Missing SDK/live-runner suites
report =SKIP= in that gate. Use =./make test all= or =make test-all= as the
strict CI gate with both real host runners configured. =tests/monad= also contains orchestrated two-stage
fixtures which require explicit reload coordination; loading the definitions
alone is not a proof that reload preserved state or rejected stale refs.

=make test-headless-startup-render= launches the real Vulkan renderer without
a window, requests 2x, 4x, 8x, then nil/off through the Monad render-policy
capability, and renders a frame after each accepted transition. Unsupported
device sample counts are rejected without changing the active mode; invalid
count 3 is always rejected. The fixture then captures a 256x256 RGBA frame and
asserts that the centered cube contributes visible pixels at the center (not
merely UI overlays). This catches an inverted rasterizer front-face setting as
well. It requires the built =obsidian= executable and a working Vulkan device;
it is separate from =make test=, which remains GPU-independent.
=make test-headless-matcap= renders the same cube once in PBR and once in
studio-matcap mode, then requires a consumer-visible pixel difference. It
requires a working Vulkan device and is not part of the GPU-independent suite.
=make test-headless-async-obj= sends a triangle OBJ through the real worker
parser and renderer-thread upload/publication path; it asserts that the scene
publishes one three-vertex mesh. It requires a working Vulkan device.
=make test-headless-editor-materials= exercises the editor's shared drop-path
dispatcher and Monad filesystem activation classifier without creating a native
window: scene-preview extensions map to asset previews, supported image
extensions map to image previews, unknown extensions map to text editing, and
directories/no-extension files do not activate. Monad's double-click policy
matches the same file row within 300 ms and rejects a different row or a click
outside the timeout. JPG and PNG drops must assign
different uploaded texture handles to the picked mesh, and GLB, glTF and OBJ
drops must asynchronously increase the active scene's mesh count. Its GLB and
glTF imports also exercise geometry-arena growth between completed async
uploads. This covers the dispatch path invoked by the GLFW file-drop callback,
not native window-system event delivery. The same fixture renders and picks a
mesh with its material indices removed and wireframe enabled, covering selection
through the depthless wireframe pass.
Pipeline-cache writes use a same-directory temporary file and atomic rename;
unreadable cache data is ignored, and driver-rejected cache data retries with
an empty cache. Parallel headless renderer processes therefore cannot expose
a partially written cache to one another.
The capture is a raw RGBA correctness fixture, not a screenshot. Benchmark
samples never capture or write image data.
=make test-headless-sponza= runs one measured offscreen frame on the repository
Sponza scene and tears down the full renderer. It exercises the large scene's
texture upload/cache path; the test is included in =make test headless= when
=OBSIDIAN_GPU_TESTS=1=.
=make test-headless-pbr-ao= uses =assets/gltf/ABeautifulGame/glTF/ABeautifulGame.gltf=,
requires at least one imported AO-mapped mesh and a valid measured
=main_forward= GPU timestamp in every run. It primes and requires a validated
OMDL cache hit, then benchmarks five independent processes, 30 warmup frames
and 60 measured frames. Override
=PBR_AO_BENCH_RUNS=, =PBR_AO_WARMUP_FRAMES=, or
=PBR_AO_BENCH_FRAMES= for local investigation; retain the defaults for
comparable results. This measures the whole forward pass with AO-capable
materials, not AO-only shader cost or an AO-on/off performance delta.
It is included in =make test headless= when =OBSIDIAN_GPU_TESTS=1=.
=make test-headless-pbr-lighting= benchmarks the same one-mesh glTF fixture
with directional sun intensity 3 and 0. Both modes run five processes, 60
measured frames, and a warm OMDL cache; warmup is disabled so the sun-enabled
case captures initial cascade rendering. Per-run reports must show a forward
GPU timestamp in both modes, sun and shadow feature activation only in the
sun-enabled mode, actual cascade task work only with the sun, and identical
scene input. It records both forward-pass distributions without imposing a
hardware-fragile timing threshold. The zero-sun policy also bypasses direct-sun
BRDF and the shadow-dependent specular-occlusion term in mesh and SDF shaders.
It is included in =make test headless= when =OBSIDIAN_GPU_TESTS=1=.

=make test-asan= rebuilds =test-native= in the separate
=build/asan/native/= directory with AddressSanitizer and UndefinedBehaviorSanitizer;
LeakSanitizer is enabled at runtime. It instruments the C translation units
compiled by those native test recipes, including focused production-C seams.
It is **not** a full linked-engine, Vulkan-driver, or live Monad/JIT sanitizer
run. System libraries and GPU drivers are outside this coverage. The standard
test suite remains uninstrumented; =./make test headless= runs both suites in
sequence and then the CPU benchmark family. Set =OBSIDIAN_GPU_TESTS=1= to append
the real headless pixel and Vulkan-validation smokes.
The first LSan run exposed a 144-byte leak in the skeletal-animation test
fixture: reinitializing its graph discarded the test-owned index. Fixture
reinitialization now destroys that index before clearing the graph.

Geometry arenas no longer reserve hundreds of MiB at window startup. The
vertex arena starts at 4 KiB, the index arena at 4 MiB for its existing
1,048,576 sequential indices, and upload staging at 64 KiB. Geometry pools and
staging grow geometrically when a preflighted upload exceeds capacity, copying
the used GPU prefix before replacing an arena. Growth is a cold path and waits
for device idle; normal allocations that fit do not wait or allocate new GPU
buffers. This reduces configured initial capacity, not a claim about total
process RSS or driver-resident memory.
Texture pages start at 256 KiB, grow to fit an individual larger request, and
increase geometrically for subsequent pages.

* glTF cache and per-mesh footprint

=Mesh= no longer embeds 256 bone override matrices in every mesh record.
=MeshBoneOverride= storage is allocated on the first override, bounded to
=min(jointCount, 256)=, and released on reset/removal/destruction. On this
x86-64 C23 build, =sizeof(Mesh)= is 432 bytes; the native contract asserts the
record stays below 8 KiB and verifies lazy allocation, bounds and release.
Run it with =make test-mesh-bone-overrides=; =make test= includes it when Vulkan
headers are present.
Because =obsidian.h= re-exports =renderer.h=, this changes the public =Mesh=
layout; downstream C consumers must rebuild against the matching header and
library rather than mixing old binaries with this build.

The glTF staging array starts with capacity one and grows geometrically. OMDL
cache hits reserve from the validated mesh count before staging. The former
64-entry initial reservation cost 1,337,344 bytes for the 20,896-byte old
=Mesh= record, even for a one-mesh scene; the same one-mesh staging allocation
is now 432 bytes. These figures are the requested staging-array allocation,
not total process memory.

OMDL source identity hashes the exact root-file bytes already retained by
=cgltf_parse_file=, then hashes decoded buffer contents. This preserves the
cache digest inputs while avoiding separate pre-parse and post-parse reads of
the root document. =make test= checks that retained-byte hashing produces the
same digest as the streaming file helper. The documented cold/warm GPU asset
benchmark is a separate run; the native sanitizer target does not claim that
renderer integration.

On the RTX 3060 / Ryzen 7 3800X workstation, the 9,000-vertex, 143-meshlet
headless fixture was measured at 256x256 for nine independent processes per
cache mode:

| Cache mode | Load wall median | Load CPU median | Wall CV | GPU geometry upload median |
|------------+------------------+----------------+---------+-----------------------------|
| Cold OMDL  | 12.118 ms        | 11.511 ms      | 4.37%   | 112.3 us                    |
| Warm OMDL  | 10.891 ms        | 10.264 ms      | 2.39%   | 111.8 us                    |

Run =python3 tools/bench/engine_bench.py --scene tests/fixtures/async-meshlet-growth.gltf --headless --width 256 --height 256 --runs 9 --warmup-frames 0 --frames 1 --scene-cache MODE --output build/bench/RUN= once with =MODE=cold= and once with =MODE=warm=; use a distinct new =RUN= directory each time.
The prior five-process baseline was substantially noisier (25.1% cold and 53.6%
warm load-time CV), so those medians do not establish a controlled before/after
speedup. Current warm/cold medians differ by 1.23 ms (~10% of cold), but the
runs are independent rather than paired. Geometry upload time is GPU timestamp
time; the CPU changes do not affect it. Current whole-process peak RSS remains
about 244--246 MiB and includes Vulkan/LLVM/driver allocations; Massif reported
a 33.36 MB heap peak, including external runtime allocations.

The warm path still parses glTF metadata and calls =cgltf_load_buffers= before
the OMDL hit can be accepted, preserving decoded-buffer content validation.
The aggregate load timer does not isolate the cost of those steps; add scoped
CPU timings before attributing the remaining ~10 ms. Do not replace content
validation with timestamp-only checks. Linux hardware counters reported a
1,486,043 median cache-miss count for the warm benchmark process, but the
counter scope includes initialization and teardown, not just the loader. The
same profile attributes 32 MiB of live Vulkan allocation to shadow resources;
changing that footprint needs a separate quality/correctness contract.

* Selection and transform interaction

In the hierarchy, Monad owns single-select, Ctrl-click toggle and Shift-click
range/append decisions; the native adapter applies them to scene nodes. In the
viewport, Shift-click appends mesh/SDF picks without clearing existing scene
selection. Click-drag from empty background
to select objects by their projected bounds: left-to-right drags select fully
enclosed bounds; right-to-left drags select intersecting bounds. Selected visible
objects share one orange outline and low-alpha fill around their combined screen
bounds; the active marquee uses a blue translucent rectangle. Press =f= to frame
the selected mesh or SDF. Monad chooses the =h= visibility target: hide all
selected entries when any is visible, otherwise show them all; the host applies
that target and ancestor visibility continues to determine effective mesh
visibility. SDF primitives follow the same hierarchy
visibility; each fenced frame slot compacts visible SDFs in stable scene order,
without allocating on the frame path. SDF visibility changes only dirty the
per-slot upload; they do not write into in-flight mapped buffers. =r= then =x=
rotates around negative world X so its drag direction is inverted; Y/Z and
gizmo-axis behavior are unchanged.

* Native reproducibility

The UTF-8 suite checks overlong encodings, surrogates, invalid leaders,
incomplete sequences and 20,000 deterministic malformed strings. The reload
stats suite checks sample eviction and nearest-rank p50/p95/p99. The watcher
suite checks first observation, debounce, acknowledgement, polling and reset.
These are intentionally small C seam tests: Monad integration assertions are
in =tests/monad=. All test binaries are generated under =build/tests/=.

* Font profiling

=OBSIDIAN_FONT_PROFILE=1= enables counters for L1/hash cache hits, glyph misses,
FreeType rasterization, atlas uploads, atlas resizes, emitted glyphs, text CPU
time and upload CPU time. A summary is written at font destruction; there is
no per-glyph logging on the frame path. Timings are CPU wall times, not GPU
completion or Vulkan frame-pacing metrics. Compare the same scene, font size,
window resolution, warmup and input sequence before asserting improvements.

A genuinely complete font optimization ratchet additionally needs GPU timestamp
queries, sampled glyph rasterization time, upload bandwidth, per-frame atlas
mutation counts, p50/p95/p99 frame times, a capture of multilingual/fallback
workloads, and end-to-end MSDF atlas rendering. None is supplied by this host.

* Engine frame profiling and optimization baseline

=./make bench engine= (backend: =make bench-monad=) runs an offscreen Vulkan
workload from =tests/monad/bench-scene.mon= by default (no editor window),
using 120 warm-up and 600 measured frames per process, five processes by
default. Reports go to =BENCH_OUTPUT= (default
=build/bench/monad-<UTC timestamp>/=) and include CPU frame stages, Vulkan
timestamp duration,
geometry upload, acquire/fence/record/submit/present, lifecycle timings, host,
GPU, and driver metadata. Use =./make bench engine --runs N
--warmup-frames N --frames N --asset-root PATH --manifest PATH --output DIR=
to set the workload.

The timestamp profiler must report valid GPU samples whenever timestamp
support is enabled. It writes TOP_OF_PIPE and BOTTOM_OF_PIPE queries around
the recorded command buffer and collects them only after its frame fence
signals. A support flag without captured samples is a benchmark failure.
Frame CPU stages include event polling, swapchain maintenance, scene/physics/
camera/editor update, geometry upload, acquire and image-fence waits, command
recording, queue submit, and present.
CPU recording time also splits render-graph callback execution,
transmission/transparent recording, and UI recording inside
=command_record_ns=. These use the monotonic CPU clock and are not GPU pass
durations. Their sum need not equal the outer interval: render-graph setup,
query commands, transitions, and timer overhead lie outside or straddle those
subscopes.

The latest 600-frame 1280x720 profile observed command-record p50 111.9 us,
render-graph p50 66.6 us, transmission/transparent p50 10.5 us, and UI p50
1.75 us. GPU frame p50/p95 was 1.463/2.670 ms while boundary utilization
snapshots showed 84-99% device-wide busy. This proves reporting is wired, not
that timings are stable baselines. Raw report:
=build/bench/profile-final-20261012/run-01.json=.

2026-06-21, Ryzen 7 3800X + RTX 3060, five runs × 600 measured frames:

| Metric | Before | After |
|--------+--------+-------|
| CPU frame update p50 | 2.486 ms | 0.0155 ms |
| Total CPU frame p50 | 2.650 ms | 0.196 ms |
| Swapchain-maintenance p50 | 2.470 ms | 0.000080 ms |
| GPU command-buffer p50 | 0.118 ms | 0.109 ms |

The measured update bottleneck was a swapchain recreated every frame after
either stale-state flag became set. Successful recreation rebuilt the Vulkan
resources but never cleared =swapchainOutOfDate= or =framebufferResized=.
Clearing both after recreation reduced median update time by about 99.4% and
median total CPU frame time by about 92.6% on this workload. The GPU change is
within workload/device variation; no GPU optimization is claimed. The
remaining median app draw includes image-fence and presentation pacing and is
not equivalent to CPU rendering cost.

This is an initial workload, not a complete engine performance suite. The
default demo's 2D vertex counters are zero because it does not exercise the
2D batch path. Window creation, app asset setup and cleanup are currently
reported as aggregate lifecycle phases; they need subphase measurements and
representative uncached asset workloads. Compare identical host, scene,
window, warm-up, frame count and input before interpreting deltas. Do not use
screenshots as performance evidence.

The historical readback-overhead figures below are not a valid source-backed
comparison. Code inspection found that the benchmark set
=context.headlessReadbackEnabled=false= after initialization, but command
recording still copied every headless frame into a host buffer. The previous
documentation incorrectly described that copy/barrier as disabled. Do not use
the recorded 1.518/1.020 ms GPU p50 values as a confirmed readback comparison.
The headless mode is now explicit: raw-image runs request readback; performance
runs do not allocate/map a readback buffer, record the image-to-buffer copy, or
record its host-read barrier. The raw-pixel regression still requests raw RGBA
output. A subsequent full build, raw-cube pixel test and headless Sponza profile
passed. The report showed =readback: null= in measured performance frames.
This validates mode separation, not a controlled readback-on/off performance
comparison.

=scene.load_wall_ns= is elapsed time around synchronous =load_gltf=, including
Vulkan waits and work scheduled to background threads. =scene.load_cpu_ns=
and =process_cpu_ns= use process CPU time, so they include engine threads and
exclude time blocked without executing. Neither load metric isolates geometry
decode, texture cook or GPU upload. =scene.geometry_upload_gpu_ns= timestamps
the geometry-copy/barrier command and excludes texture uploads. =frames.gpu_ns=
is GPU timestamp duration for the recorded frame command buffer.
The legacy =scene.source_file_bytes= field counts only the root file. Separate
=asset_inputs= stores SHA-256 and byte size for the glTF/GLB plus its referenced
local buffers and images; missing dependencies fail the headless runner.
“Cold” disables the OMDL geometry cache only; it does not flush OS file cache,
texture caches or pipeline caches. Benchmark targets resolve bundled paths
beneath =BENCH_ASSET_ROOT= (default =assets=); point it at an external asset
tree without copying user assets into the repository.

Headless performance mode submits up to =MAX_FRAMES_IN_FLIGHT= frames before
waiting to reuse a slot. Each slot owns its command buffer, color target, depth
image, HZB/transmission resources and timestamp queries; query results are
collected only after that slot's fence signals. =frames.total_ns= is host-side
per-submission wall time, including any wait when reusing a slot; it is a
throughput measurement, not end-to-end completion latency. GPU duration comes
from device timestamps. =--headless-raw= enables per-slot readback and waits
for completion before returning the image.

=make bench-monad= runs a headless workload declared in Monad from
=tests/monad/bench-scene.mon=. Each Monad module defines seven closed native
=Int -> Int= accessors for scene ID, resolution, warm-up, measured frames,
cache mode and minimum mesh count. Obsidian invokes these exports after
publication, validates their bounds, and uses them to configure the Vulkan
run. Bundled scene IDs are =1= Sponza, =2= trees.glb, =3= NodePerformanceTest,
=4= VertexColorTest, =5= xmp, =6= TransmissionTest, =7= Unicode❤♻Test,
=8= UnlitTest and =9= TextureCoordinateTest. Cache mode =0= is cold and =1=
is warm. =tests/monad/bench-scene-warm.mon= is the warm-cache companion;
=bench-scene-trees.mon= and =bench-scene-textures.mon= select the bundled trees
and TextureCoordinateTest scenes for additional workload shapes.
Adding a bundled asset requires extending the scene-ID table in
=src/monad/runtime.c=.

=make bench-portable= runs checked-in Monad modules without an external asset
pack: =bench-minimal.mon= (scene 10, triangle), =bench-instancing.mon= (scene 11,
six mesh instances) and =bench-meshlet-growth.mon= (scene 12, 9,000 vertices,
143 meshlets). These scene IDs resolve under =tests/fixtures= independently
of =BENCH_ASSET_ROOT=. Module and glTF inputs are hashed by the existing runner.
Each declares 640x360, 30 warmup and 120 measured frames. These are bounded
portable workload shapes, not a complete production benchmark portfolio.
They do not replace the missing Sponza/texture/animation assets or exercise
scripted upload contention and resize. =make profile-check= retains its
production-workload requirements.

Headless startup reports leave =first_present= null: no presentation API is
called. =first_submit= records successful queue submission; it is not a GPU
completion measurement.

GPU timestamps include the whole frame plus dynamic geometry transfer, meshlet
bounds refit, aggregate shadows and four cascade intervals, opaque main-forward,
transmission-image copy, transparent/wireframe, 2D UI, raw-image readback (only
when enabled), aggregate HZB and up to 16 mip intervals. Stage names, parents,
IDs, units and inclusive timing semantics come from the C-owned schema; JSON,
CSV, CLI stage validation and the dashboard consume that schema. Each timestamp
pair is reset and collected only after its frame-slot fence completes.
Raw JSON adds =frames[].gpu_pass_ns=; =summary.json= and =frames.csv= include
per-stage p50/p95/p99 and samples. Stage timestamps are elapsed GPU timeline
durations, not utilization, isolated shader cycles, or exclusive GPU
occupancy. Empty stages can be legitimate (for example, no HZB pipeline).

When Linux =perf= is present and the kernel permits it, the runner wraps each
measured process with =perf stat= for cycles, instructions, cache references,
cache misses, context switches and CPU migrations. Results are process-run
totals, include initialization and teardown, and are not frame-attributed.
Unsupported or inaccessible counters remain unavailable; the runner probes
permissions before using =perf=. When =nvidia-smi= is available, each engine
process also gets before/after snapshots of GPU temperature, graphics/memory
clocks, power, utilization and VRAM. These probes run outside the timed child
process. They are boundary context only—not per-frame telemetry, attribution,
or a substitute for Nsight Systems/Graphics. Other vendors and unavailable
fields remain explicitly absent.

Scenario choices and parameters live in Monad scripts; C resolves bounded
scene IDs and drives Vulkan, while the existing Python runner handles process
launch, aggregation and terminal output. The embedded compiler currently
cannot link native exports that use =string-length=, =string-ref= and
=char->integer=; a direct compiler probe failed with unresolved symbols.
Therefore arbitrary path-valued Monad manifests and a pure-Monad OS runner
are not available with the current compiler/runtime ABI. Do not claim this
benchmark stack is wholly implemented in Monad.

The embedded Monad compiler previously failed native materialization because
its internal call-profiler hooks were hidden by the shared-library export map.
=monadc/src/embed/native_compile.c= now binds those three internal hooks as
ORC absolute symbols without exporting them publicly. The integrated
=make bench-monad= run proved module publication, scalar export execution,
headless scene loading, and a complete 600-frame measurement. This workload
does not register a per-frame Monad callback; Monad frame callback coverage
remains unverified: attempting an opaque =Frame= callback is rejected by
MonadC with =MONAD-C0004= (no closed native ABI). A separate attempt to invoke
the manifest host binding from a compiled Monad function hit =MONAD-C0005=
(missing QTT resource certificate); the supported scalar-export manifest
avoids that unsupported effect path. =make test-monad= needs
=OBSIDIAN_MONAD_TEST_RUNNER=.

=BENCH_COMPARE_TO= accepts a saved =summary.json=. The runner compares
configuration identity (host/CPU, Vulkan device/timestamps, compiler flags,
workload and asset hashes, resolution, cache mode and instrumentation) while
deliberately allowing source/binary hashes to differ between baseline and
candidate. Each summary retains the individual process-level p50 samples.
Comparison requires at least five independent processes in both summaries and
uses a deterministic 10,000-resample bootstrap of the difference between the
two medians. With no threshold, it is diagnostic only. Set
=BENCH_MAX_REGRESSION_PCT= explicitly to gate: exit 0 when the upper 95% bound
is at or below the limit, exit 1 when the lower bound exceeds it, and exit 2
when the interval overlaps the limit or configurations/replicates are
incompatible. There is no default threshold. This is an unpaired independent
run comparison; thermal/power drift can confound it, so it is not a paired
release gate.
A same-executable five-run/five-run comparison was exercised with an explicit
100% smoke limit: observed wall p50 change +0.87%, independent-run CI
[-0.47%, +2.48%], status =PASS=. The permissive limit tested the gate path; it
is not an accepted engine regression threshold or before/after optimization.

engine-owned allocation totals; the extension's usage is approximate and its
budget can change with system activity. Unsupported devices report an empty
heap list. A headless Sponza smoke reported heaps at 1266.1 MiB, 843.1 MiB and
31.4 MiB usage, with budgets 9928.0 MiB, 11948.0 MiB and 214.6 MiB respectively.

an allocation baseline.

Raw reports include Vulkan device name/vendor/device/driver/API identity and
timestamp support, queue-family index, valid-bit width, and period in ns.
The runner rejects malformed metadata and refuses to aggregate runs when device,
queue/clock metadata, or stage schemas differ. Current GPU pass values remain
inclusive same-queue durations. The profile has one-shot integration proof but
does not yet provide measured instrumentation overhead, calibrated CPU/GPU
correlation or multi-frame in-flight throughput.

The color output distinguishes GPU timestamp availability from CPU results;
it does not convert GPU timestamps into utilization or infer GPU busy time
outside the measured command buffer. In headless mode every sample waits for
its GPU fence before proceeding; this measures serialized completion latency,
not multi-frame-in-flight throughput or presentation pacing. Monad scalar
exports define the selected bundled scene, resolution, warm-up, sample count,
cache policy and mesh-count assertion. CPU stage timings are instrumented
inside the offscreen frame loop; total frame wall time includes the explicit
GPU-fence wait, while process CPU time measures CPU execution across engine
threads. Linux perf counters are process totals, not frame-attributed
measurements. Vulkan pipeline statistics, vendor GPU power/clocks/utilization,
GPU memory bandwidth and multi-frame-in-flight throughput are not captured.
Raw reports identify whole-process peak RSS from =getrusage.ru_maxrss= (Linux
KiB converted to bytes) and post-engine-teardown resident bytes from
=/proc/self/statm= (resident pages × page size). A one-process Sponza profile
observed 1288.8 MiB peak and 172.7 MiB after engine teardown:
=build/bench/profile-rss-final-20261012/summary.json=. These are process-wide
host-memory observations; they do not attribute allocations to engine
subsystems or measure Vulkan heap/VRAM usage.
