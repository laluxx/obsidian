#+TITLE: Obsidian Cycle 58 — Continuous Scene Inspector Transactions
#+DATE: 2026-10-12
#+STARTUP: overview

* The real vertical slice

Cycle 57 routed sphere position and base PBR fields through the shared undo
journal, but emitted one command for each drag sample; radius, CSG/smoothness
and emission still wrote directly into renderer primitives.

Cycle 58 connects the production editor controls to a single coalesced scene
transaction:

=field_vec3 / field_float / field_dropdown / field_vec4_color=
 -> persistent =ObsSdfPanelProxy= -> =obs_sdf_property_begin/preview/commit=
 -> =obs_sdf_inspector_preview_edit= -> production =scene.sdfs=
 -> fence-slot deferred =flushSdfSSBO= -> Vulkan.

- The first valid control delta opens a private scene-epoch group. Later
  samples replace one staged original/latest record; a sustained edit does
  not fill the 64-command history.
- Mouse release or picker close commits one existing Emacs-like undo command.
  Escape, focus loss, selection change, and closing the Inspector request
  conflict-checked cancellation. The Inspector refuses to close if rollback
  remains conflicted.
- The bridge checks both ticket and group identity. It cannot join a viewport
  transaction or adopt a replacement group opened by another caller.
- Supported sphere state is translation, base RGBA, metallic, roughness,
  radius, CSG operation/smoothness, and emission RGB/strength. Values are
  copied and validated before the journal publishes the primitive.
- Modal picker and drag pointers refer to persistent editor-owned proxy state.
  Non-sphere SDF fields retain their previous direct-edit behavior.

* Deliberate limits

- Only translation-only sphere primitives are journal-backed. Boxes, terrain,
  mesh and glTF editors are not routed through a sphere-state record.
- History remains a bounded in-memory journal. Nested transactions, durable
  undo and full Emacs command-loop amalgamation are not added.
- External scene writers must participate in the journal or cause a checked
  conflict. Mutation remains owner-thread-only.
