#+TITLE: Obsidian Cycle 57 — The actual SDF sidebar joins Emacs-like scene undo
#+DATE: 2026-10-12
#+STARTUP: overview

* Why this slice exists

Cycles 51–56 added shared sphere identities, viewport picking/dragging,
transaction cancellation and Emacs-style undo. The production graphical SDF
inspector (=render_sdf_inspector= in =src/editor/editor.c=) still wrote the
same sphere's primitive storage directly, bypassing that journal. Cycle 57
routes its supported fields through the existing scene journal rather than
creating a parallel property model.

* Production contract

=editor field controls -> persistent proxy storage ->
 src/editor/sdf_property_bridge.c -> shared scene-epoch ticket ->
 src/scene/sdf_inspector.c -> real scene.sdfs -> fence-slot SDF SSBO -> Vulkan=.

- For spheres, Position XYZ, base RGBA, Roughness and Metallic are submitted
  as validated copies, not written into the live scene before validation.
  Position and material changes in one render pass produce one undoable record.
- A sphere created through ordinary scene UI obtains a lazy stable ticket;
  it need not originate in compiled Monad or the external agent.
- Sidebar edits do not join or change an open speculative viewport transaction;
  they fail closed. Invalid values and stale selections reject without
  changing the supported scene properties or stealing selection.
- The modal color picker retains its target across frames. Journal-backed UI
  fields therefore use persistent proxy storage. On a different sphere, the
  panel closes only its own picker and clears only pointer capture it owns.
- Publication uses the existing GPU dirty-generation/fence-slot path. There
  is no shadow scene, mutation queue or second undo implementation.

* Deliberate limits

- Radius, primitive shape/CSG/smoothness, emissive RGB and strength,
  non-sphere properties, and texture edits are not in this journal. They keep
  prior direct-edit behavior and are not undoable. Out-of-band direct edits
  can make earlier journal undo reject on object-state conflict.
- Sustained sidebar float drags produce multiple undo commands. Full Emacs
  command-loop boundaries and automatic amalgamation are not implemented.
- Scene mutation remains owner-thread-only; no QTT-certified effect is added.
- Visible GUI, color-picker and physical display behavior needs workstation
  verification; native tests do not substitute for that interaction.
