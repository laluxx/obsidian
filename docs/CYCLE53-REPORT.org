* History design

Inverse history is recorded when an undo changes a sphere. A saved pending
index makes repeated undos walk earlier records, while an explicit command
boundary changes the next ordinary undo to reapply a previous change. A
separate undo-only entry skips recorded inverse operations. Explicit redo
consumes the last undo-generated command without adding another inverse.
Original records persist after branching edits; their active state prevents
undo-only from undoing an already undone original change.

Command groups can contain multiple property writes and multiple sphere
identities. Each reverse transaction is preflighted against virtual live
states before publishing any part. Thread, effect, scene epoch, stale ticket
and direct foreign mutation protection are retained. Storage remains bounded
at 64 records, including undo-generated inverse records, and static only.
