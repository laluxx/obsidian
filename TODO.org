* Intent and reviewed evidence

This is the ONE active Obsidian queue.  First audited from
=obsidian.tar(1).gz= on 2026-10-09, then updated during cycles 1 and 2 on
2026-10-10.  The original handwritten backlog is preserved unchanged at
=docs/archive/original-TODO.org=.  Cycle 1 source work is present but
requires integration verification against an actual MonadC/Vulkan build.
The original engine archive contained
31 first-party C files and their first-party headers, and 17 shader files (excluding
vendor sources), totaling approximately 35,353 non-vendor C/header/shader
source lines. Existing Monad integration is visible in =keychords.[ch]= and
=tests/keychords-monad.c=; a complete engine REPL/gameplay module host is not
yet present in the reviewed source. The README's embedded Scheme claim should
therefore be treated as historical/aspirational until proven by executable
code. The monadc repo and complete run-time assets are not in this archive.

*Vision*: preserve the working Vulkan engine and its excellent GPU-oriented
foundations, embed one coherent Monad runtime into the existing C host, then
progressively move *editor/game/scene/animation/render-graph policy and
algorithms* into native compiled Monad. Live editing, type-driven APIs and
reloadable games are first-class requirements. C remains a carefully delimited
platform/driver/real-time/legacy bridge until individual replacements meet
strict behavioral, safety and performance gates. "100%" means complete
feature/ownership migration, NOT reflexively zero lines of C or removal of
proven Vulkan/Jolt/miniaudio libraries.

This is not a Lisp syntax redesign. Monad source retains Monad's existing
syntax and semantics. The host must not invent a shadow interpreter or a
second type system. Use QTT, indexed types, effects, resource capabilities,
and typed staged graphics only where the compiler *actually supports them*;
missing language features become named MonadC prerequisites and tests rather
than imaginary APIs or unsafe application-side workarounds.

* Priority zero audit findings / source safety ledger

These are static-review findings or validation gaps, not claims of observed
runtime crashes. All require executable reproduction on a fully provisioned
build. =OBS-001= must install prerequisites; in this review the standalone
=make test-renderer2d-capacity= was blocked by a missing system Vulkan header.

- =P0= =gltf_loader.c:load_gltf_textures=: =data->textures_count= iterates into
  fixed =MAX_TEXTURES= arrays without an upfront bound; =strcpy= copies a
  1024-byte temporary path into =gltf_texture_paths[][512]=. Audit all asset
  paths and untrusted file extents before exposing script-based loading.
- =P0= =src/audio/audio.c=: mixing callback reads mutable =AudioBuffer= fields while
  =play/stop/seek/fill= update them without the callback's mutex. A looping
  zero-frame buffer cannot advance the mixer. Audio must not host Monad calls.
- =P1= =editor/text_editor.c:buf_delete=: deletion history uses a 4096-byte
  snapshot; deletion beyond it can lose information required for undo parity.

  routines may terminate the process on failure. Hot reload requires a
  recoverable host resource protocol.
- =P1= =src/graphics/render_graph.c=: dependency/resource caps are silently exceeded,
  resource IDs are dereferenced without validation in execution, and
  =rg_reset= clears both resources and passes despite its header claiming
  registered resources survive. Graph is a useful starting point, not yet a
  sufficient correctness oracle for dynamic script-authored passes.
- =P1= =window.c: initWindow=: =physics_init= is inside =s_editor_enabled=;
  runtime physics thus does not initialize when the editor is off, despite
  =beginFrame= calling =physics_step=.

  release profile; the hardware/asset-dependent demo has no reproducible
  benchmark manifest. Real production-performance claims need release builds.
- =P1= =README.md=: claims an embedded Scheme REPL and broad hot reload;
  implementation evidence presently centers on Monad keybindings and
  specialized asset/pipeline subsystems. Document demonstrated behavior.
- =P2= =src/graphics/renderer.c= and =src/graphics/vulkan_setup.c= are 3.8k/4.1k-line monoliths;
  =src/editor/editor.c= is 4.5k lines. Break out capabilities/ownership by proven

  module unloading, multiworld isolation and safe resource revocation hard.
  A typed generation-indexed handle boundary should precede exposing them.

C Vulkan renderer and C camera data*, compile a camera navigation function

result on screen. Alter the function from the REPL while the world runs,

* Explicit compiler/QTT research obligations (separate authority)

These are *requirements to investigate*, not assertions the language already
provides the feature. File upstream MonadC tasks when a minimal repro fails:

- Native, C ABI and dynamic-call representations for sized vectors, by-value
  structs, strings, stable callbacks and Vulkan-compatible GPU buffer layouts.
- Exact semantics for owned, affine/linear, borrowed and pinning data through
  thread and GPU completion boundaries; a Vulkan fence cannot be "proved"
  away by a compile-time annotation without an actual completion protocol.
- Effect/capability restrictions for mutating a world, enqueueing GPU commands,
  scheduling physics, writing assets and evaluating REPL expressions.
- Incremental typed module recompilation, typed function publication, code
  reclamation and state schema migrations with rollback.
- Native performance profile for callbacks, loops, arrays, SIMD, arena lifetime,
  cancellation, multi-thread attachment and diagnostic spans.
- Feasibility of typed staged material/shader generation with trustworthy
  reflection; it may remain a bridge to GLSL/SPIR-V indefinitely.

| Editor interactions  | replay key/gizmo/text/inspector actions  | input-to-visible latency                |
| Long game session    | 6h+ stress, hot reload and asset churn   | RAM/VRAM drift, leaks, p99 latency      |

Performance and latency thresholds are established from OBS-004 and explicitly
accepted per device class. Do not invent absolute millisecond budgets that
have not been measured. Make benchmark flags and data reproducible.
